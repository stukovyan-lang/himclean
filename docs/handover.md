# HimClean — передача сайта и обслуживание

Инструкция для владельца сайта и его разработчика. Сайт готов к запуску:
он уже в боевом режиме и после выкладки на домен открыт для поисковиков.

## Что внутри

- Многостраничный сайт на Next.js 15: главная, 9 страниц услуг, «Услуги»,
  «Наши работы», «Отзывы», «О нас», «Контакты», «Как мы работаем»,
  «Вопросы и ответы».
- Все тексты, контакты, фото работ и отзывы лежат в репозитории (папки
  `content/`, `assets/`, `public/`). Базы данных и админки нет: правка —
  это изменение файла и новая выкладка.
- `CLAUDE.md` — подробное техническое описание и правила проекта для
  разработчика. Читать перед первой правкой кода.

## Что понадобится

1. **Аккаунт GitHub** (бесплатный) — там хранится код.
2. **Хостинг.** Рекомендуем **Vercel** — проще всего, всё работает сразу.
   Бесплатный тариф Hobby по правилам Vercel только для некоммерческих
   сайтов, для сайта бизнеса нужен тариф **Pro** (около $20 в месяц).
   Альтернатива — свой сервер (VPS) с Node.js, см. вариант Б.
3. **Домен** и доступ к настройкам DNS у регистратора (например, hoster.by).

## Шаг 1. Код — на ваш GitHub

Код лежит в публичном репозитории подрядчика: https://github.com/stukovyan-lang/himclean

Чтобы он стал вашим, есть два способа.

- **Передача (рекомендуем).** Подрядчик переносит репозиторий на ваш
  аккаунт GitHub (Settings → Transfer ownership). Вам придёт письмо —
  примите перенос. Вся история изменений сохранится, а сделать репозиторий
  закрытым можно потом: Settings → Change visibility → Private.
- **Копия.** На github.com: «+» → Import repository → вставьте адрес выше.
  Получится ваш собственный репозиторий, его сразу можно сделать Private.

Не используйте кнопку Fork, если хотите закрытый репозиторий: копия
публичного репозитория через Fork закрытой не становится.

## Шаг 2, вариант А. Vercel (рекомендуем)

1. vercel.com → Sign Up → войти через GitHub.
2. Add New → Project → выбрать репозиторий `himclean` → Import.
3. Настройки сборки не трогать: Vercel сам определит Next.js и pnpm.
4. **Environment Variables** — добавить:

   | Переменная | Значение | Обязательна |
   |---|---|---|
   | `NEXT_PUBLIC_SITE_URL` | `https://ваш-домен.by` — без `/` в конце | **да** |
   | `YANDEX_METRIKA_ID` | номер счётчика Метрики (только цифры) | нет |
   | `GOOGLE_SITE_VERIFICATION` | код из Google Search Console | нет |
   | `YANDEX_VERIFICATION` | код из Яндекс Вебмастера | нет |

   **Не добавлять** `PREVIEW_UNLOCK` и `DEMO_MODE` — они для разработки.
5. Deploy. Через 1–2 минуты сайт откроется по адресу вида `himclean-xxx.vercel.app`.
6. **Домен:** Project → Settings → Domains → добавить `ваш-домен.by` и
   `www.ваш-домен.by`. Vercel покажет, какие записи DNS нужны. Обычно это:
   - запись `A` для `@` → `76.76.21.21`
   - запись `CNAME` для `www` → `cname.vercel-dns.com`

   Вносите те значения, которые показывает Vercel. Записи вносятся у
   регистратора домена и применяются от нескольких минут до суток.
   HTTPS-сертификат Vercel выпустит сам.
7. Выберите основной адрес (с `www` или без), второй Vercel будет
   перенаправлять на него. `NEXT_PUBLIC_SITE_URL` должен совпадать с
   основным адресом. Если поменяли — Deployments → последний → Redeploy.

Дальше любое изменение в ветке `main` на GitHub Vercel выкладывает сам.

## Шаг 2, вариант Б. Свой сервер (VPS)

Нужны Node.js 22 или 24 (LTS), git, nginx.

```bash
corepack enable    # на Node 25+ corepack не встроен: сначала npm i -g corepack
git clone https://github.com/ВАШ_ЛОГИН/himclean.git && cd himclean
pnpm install
echo "NEXT_PUBLIC_SITE_URL=https://ваш-домен.by" > .env.production
SKIP_CONTRAST_CHECK=1 pnpm build
pnpm start -p 3000
```

- Не ставьте зависимости с `--prod`: инструменты сборки лежат в devDependencies.
- Если сборка остановилась с сообщением про `NEXT_PUBLIC_SITE_URL` — не
  задан домен. Без него все ссылки для поисковиков указывали бы на
  `localhost`, поэтому сборка сознательно не проходит.
- `SKIP_CONTRAST_CHECK=1` нужен, если на сервере нет Chrome. Без этой
  переменной послесборочная проверка контраста не запустится, и сборка упадёт.
- `pnpm start` держите запущенным через pm2 или systemd. nginx
  проксирует домен на `localhost:3000`, сертификат выпускает certbot.
- После каждой правки: `git pull`, `pnpm install`, `pnpm build`, перезапуск.

## Шаг 3. После запуска

1. Проверьте `https://ваш-домен.by/robots.txt` и `/sitemap.xml`: должны
   открываться, и в них должен стоять ваш домен.
2. **Google Search Console** (search.google.com/search-console): добавить
   ресурс → способ «HTML-тег» → значение `content="…"` из тега записать в
   `GOOGLE_SITE_VERIFICATION` → Redeploy → нажать «Подтвердить». Затем
   «Файлы Sitemap» → `sitemap.xml`.
3. **Яндекс Вебмастер** (webmaster.yandex.ru): то же самое через
   метатег и `YANDEX_VERIFICATION`, затем добавить `sitemap.xml`.
4. **Яндекс Метрика** (metrika.yandex.ru): создать счётчик на домен, его
   номер — в `YANDEX_METRIKA_ID`, Redeploy. Вебвизор выключен: он
   записывает сессии посетителей, и это сначала нужно упомянуть в
   политике конфиденциальности.
5. **Профиль на Google Картах:** в поле «Сайт» укажите новый адрес. Профиль
   уже связан с сайтом в разметке.

## Как вносить правки

Короткий путь — открыть файл на github.com, нажать карандаш, сохранить
(Commit). Vercel выложит изменения сам.

| Что поменять | Где |
|---|---|
| Телефон, адрес, мессенджеры, часы, зона выезда | `content/site.ts` — единственное место, отсюда данные идут по всему сайту |
| Тексты услуг, вопросы-ответы на страницах услуг | `content/services.ts` |
| Тексты главной | `content/demo/home.ts` |
| «О нас» | `content/demo/about.ts` |
| Отзывы | `content/demo/reviews.ts` |
| Пары фото «до/после» | `content/works.ts` |

**Город** в текстах не пишется руками: `{city}` → «Полоцк»,
`в {cityIn}` → «в Полоцке». Так тексты не разойдутся с контактами.

**Новые фото работ** (нужен компьютер с Node.js и копией репозитория):
положить JPEG в `assets/works/`, выполнить
`node scripts/process-work-photos.mjs`, добавить запись в `content/works.ts`
(пара «до/после») или в `images` нужной услуги в `content/services.ts`.
Описание кадра (`alt`) — 10–125 символов, своё у каждого фото.

**Новый отзыв:** скриншот в `assets/incoming/reviews/` с уже **вырезанными
именем, номером, адресом и аватаркой** клиента. Затем
`node scripts/process-demo-images.mjs` и запись в `content/demo/reviews.ts`
с текстом отзыва. Выдумывать и «улучшать» отзывы нельзя.

**Перед выкладкой** разработчик запускает `pnpm lint`, `pnpm typecheck` и
`pnpm build`. Сборка намеренно падает, если что-то нарушает правила сайта:
нет описания у фото, два заголовка `h1` на странице, слишком длинный
заголовок для поиска. Это защита, а не поломка: сообщение говорит, что
поправить.

## Что осталось на ваше усмотрение

- `pnpm seo:check` печатает 22 пункта: на страницах услуг есть
  утверждения, которые не были подтверждены (например, время сушки,
  формат выезда). Владелец решил оставить их как есть.
- Названия юрлица на сайте нет: владелец самозанятый. Номер паспорта на
  сайт не выводить. Список вопросов — `docs/client-questions.md`.
  Сайт запущен с ними как есть. Если что-то не так — поправьте текст в
  `content/services.ts`.
- Цены на сайте не публикуются намеренно.
- Временные проекты подрядчика на Vercel (`himclean`, `himclean-demo`)
  подрядчик удалит после переезда на ваш домен.
